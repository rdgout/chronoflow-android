```kotlin
fun Base64URL.attestation(credentialID: ByteArray, clientDataJSON: ByteArray, attestationObject: ByteArray,
                          transports: List<String>? = null): ApiPasskeyAttestation   // id == rawId == encode(credentialID); type PublicKey
fun Base64URL.excludedCredentialIDs(options: ApiPasskeyCreationOptions): List<ByteArray>  // strict decode of each id; bad → InvalidEncoding
fun interface PasskeyRegistrationProviding { suspend fun registration(challenge: ApiPasskeyRegistrationChallenge): ApiPasskeyAttestation }
class DeterministicRegistrationProvider(
    private val provide: suspend (ApiPasskeyRegistrationChallenge) -> ApiPasskeyAttestation = { c ->
        Base64URL.attestation(("credential:" + c.options.challenge).encodeToByteArray(),
            ("client-data:" + c.options.challenge).encodeToByteArray(),
            ("attestation:" + c.options.challenge).encodeToByteArray(), listOf("internal")) },
) : PasskeyRegistrationProviding
```

`CredentialClient` gains `suspend fun createPasskey(requestJson: String): String = throw PasskeyFailure.Unavailable` (a **default** body, so 5b's test fakes keep compiling). It returns `registrationResponseJson`.

`PasskeyJson` gains:
- `creationJson(options: ApiPasskeyCreationOptions): String` = `ApiJson.request.encodeToString(ApiPasskeyCreationOptions.serializer(), options)` (0d's `ApiJson` is an object holding `response` and `request`; no new `Json` instance). The server options are already WebAuthn JSON (`toBrowserArray`), which is what `CreatePublicKeyCredentialRequest` takes (`03 §9.4`). Re-serialising from the DTO sends only known members.
- `attestation(responseJson: String): ApiPasskeyAttestation`, built from parsed fields (never forwarded raw, `03 §9.4`):
  1. Parse as `JsonObject`; malformed → `PasskeyFailure.Unavailable`.
  2. `type` must be `"public-key"`, else `Unavailable`.
  3. `rawId` (string, required) → `Base64URL.decodeLenient`; `id` (string, required) → `decodeLenient`; bytes differ → `PasskeyFailure.InvalidEncoding` (5b's assertion rule).
  4. `response.clientDataJSON` and `response.attestationObject` (strings, required) → `decodeLenient`; missing → `Unavailable`.
  5. `response.transports`: if a JSON array, keep the string elements with length 1–32, at most the first 8; an empty result → `null`. Otherwise `null` (§9 OQ-10d-4; the server 422s on `null`, so `null` must be **omitted** on the wire: 0d declares `transports: List<String>? = null` and `ApiJson.request` has `encodeDefaults = false`, so a null default is not written even though `explicitNulls = true`).
  6. Return `Base64URL.attestation(rawIdBytes, clientData, attestationObject, transports)`. Every other member (`authenticatorAttachment`, `clientExtensionResults`, `response.publicKey`, …) is dropped.

`SystemPasskeyRegistrationProvider.registration(challenge)` [F `SystemPasskeyRegistrationProvider.swift:19–33`]:
1. `currentCoroutineContext().ensureActive()`.
2. `Base64URL.decode(options.challenge)`, `Base64URL.decode(options.user.id)` (strict), `Base64URL.excludedCredentialIDs(options)`. Any failure throws `InvalidEncoding`.
3. `options.rp.id.isEmpty()` → `Unavailable`.
4. `return PasskeyJson.attestation(client.createPasskey(PasskeyJson.creationJson(options)))`.

`CredentialManagerClient.createPasskey(requestJson)` (`…/cd/passkey/`), same pattern as 5b's `getPasskey`:
1. `anchor.current() ?: throw Unavailable`; the shared `pending` `AtomicBoolean` busy → `Busy`.
2. `credentialManager.createCredential(activity, CreatePublicKeyCredentialRequest(requestJson))`; the result must be `CreatePublicKeyCredentialResponse`, else `Unavailable`; return `registrationResponseJson`.
3. `catch (e: CreateCredentialException) { throw e.toPasskeyFailure() }`; `finally { pending.set(false) }`. `CancellationException` is rethrown.

| `CreateCredentialCancellationException` | `Canceled` | silent; prompt stays open with the password restored |

| result not `CreatePublicKeyCredentialResponse`; no attached activity | `Unavailable` | registration failure message |

Members added to `SettingsSecurityModel` (constructor gains `registration: PasskeyRegistrationProviding? = null`, `deviceName: suspend () -> String = { "Android" }` — the default is only for 10c's existing tests; `:app` always passes the real one). 10c keeps all UI state in `SecurityState` (a `StateFlow`) and never stores a password in the model (10c §5.2, "typical mistakes"); 10d follows both rules:

- `SecurityState` gains `passkeys: List<ApiPasskey>? = null` (null = not loaded), `passkeysUnavailable: Boolean = false`, `removal: ApiPasskey? = null` (`offline` already exists). A private `registrationCanceled` flag lives in the model, not in the state.
- `showPrompt(action, removing: ApiPasskey? = null)` (iOS l.103–110): as 10c, plus `removal = removing`. `cancelPrompt()` also sets `removal = null`.
- `companion object { const val passkeyRegistrationSupported = true }` (iOS gates on iOS 17.4; Credential Manager creates passkeys from API 28 through Play services and minSdk is 29). `canRegisterPasskey = registration != null && passkeyRegistrationSupported`.
- `registrationFailure = "We couldn't register that passkey. Please try again."`, `registrationExpired = "The passkey registration request expired. Please try again."`.

**`loadPasskeys()`**: `started = generation`; `perform(ListPasskeys)`; if `generation != started` or cancelled or not `Passkeys` → return; `passkeys = list`, `passkeysUnavailable = false`, `offline = false`. `CancellationException` → rethrow. Any other failure (only if `generation == started`): `DataFailure.Offline` → `offline = true`; then `if (passkeys == null) passkeysUnavailable = true`. A later failure keeps an existing list.

**`run(change, work)`** must behave exactly as Swift l.139–218 (10c ports it; check):
- busy = true, errors and message cleared; `busy` reset in `finally` only when `generation == started`.
- Success: `retryAt = null`, `offline = false`; `Passkeys(list)` → `passkeys = list`, `passkeysUnavailable = false`; `PasskeyCreation`, `PasskeyAdded` → nothing. Return `true`.
- Keep 10c's catch order (`StaleSessionException` → `ensureActive()`, return false; then `CancellationException` → rethrow). Add `catch (e: PasskeyFailure)` (5b's `sealed class PasskeyFailure : Exception`; 10c catches only `DataFailure`, so without this clause every registration error would crash): `Canceled` → `registrationCanceled = true` (if current generation), return `false`, **no message**; any other case (if current generation) → `message = failureMessage(change)`, return `false`.
- `Offline` → `offline = true`, `message = "Needs a connection."`. `Throttled(s)` → `retryAt = now + max(0, s)`, `message = "Too many attempts."`.
- `Validation(fields)`: per field: `credential` or `name` → `message = registrationFailure`; `challengeId` → `message = registrationExpired`; key `The provided password was incorrect.` → `errors[field] = key`; (the 2FA/password keys are 10c's); anything else → `errors[field] = "Check the highlighted field."`. Empty fields → `message = failureMessage(change)`.
- Any other `DataFailure` (`Server`, `Unsupported`, …) → `message = failureMessage(change)`: `PasskeyCreationOptions` and `AddPasskey` → `registrationFailure`; `EnableTwoFactor`/`ConfirmTwoFactor` → 10c's; else `"Something went wrong"`.

**`submitPrompt(password: SecretField)`** (10c's guards unchanged: return without clearing when there is no prompt, the value is empty, `busy` or `locked`). For a non-passkey action nothing changes. For `RemovePasskey` 10c's order stays: read, **clear**, then `submitPasskeyPrompt(action, value)`. For `AddPasskey` read the value but clear the field only **after** `submitPasskeyPrompt` returns and only when the registration was not cancelled; this is how Android keeps the iOS "cancel restores the password" behaviour (iOS sets `promptPassword = password`) without the model holding the password. The field is disabled while `busy`.

**`submitPasskeyPrompt(prompt, password: String)`**:
- `RemovePasskey`: `target = removal ?: return`; if `run(RemovePasskey(target.id, password))`: `prompt = null`, `removal = null`, remove `target.id` from `passkeys`, `message = "Passkey removed"`, then `loadPasskeys()`.
- `AddPasskey`: `registrationCanceled = false`; `done = run(PasskeyCreationOptions(password), work = { register(password) })`.
  - `done` → `prompt = null`, `message = "Passkey added"`, `loadPasskeys()`.
  - else if `registrationCanceled` → `registrationCanceled = false`; `submitPrompt` leaves the `SecretField` uncleared, so the typed password is still in the prompt (the user can tap again).
  - else if `message == registrationFailure || message == registrationExpired` → `prompt = null` (the message then shows as the snackbar).
  - else (wrong password, offline, throttle) → the prompt stays with its error / message.

**`register(password)`** (private):
1. `registration ?: throw PasskeyFailure.Unavailable`.
2. `val r = perform(PasskeyCreationOptions(password))`; not `PasskeyCreation` → `throw DataFailure.Server(null)`. The password is checked **here**, before the system sheet (P20), so a typo never leaves an orphan passkey.
3. `Base64URL.decode(challenge.options.challenge)`; `Base64URL.decode(challenge.options.user.id)`; `challenge.options.rp.id.isEmpty()` → `Unavailable`.
4. `ensureActive()`; `attestation = registration.registration(challenge)`; `ensureActive()`.
5. `return perform(AddPasskey(ApiPasskeyRegistrationInput(challenge.challengeId, name = passkeyName(deviceName()), credential = attestation)))`.

`passkeyName(raw)` [R]: `raw.trim()`, capped at 255 code points (server `name` 1–255, trimmed); if blank use `Build.MODEL` from `:app` (the lambda handles it; the model just trims and caps). §9 OQ-10d-11.

`clearSecrets()` (10c) must also set `removal = null` (iOS l.246); it keeps `passkeys` (iOS keeps them) and still bumps `generation`.

## 8. Review checklist (Opus reviewer)

- [ ] **Capability:** no passkey UI, route or seed is reachable with `PasskeyCapability.Shipped`; the Security row also requires `passkeyCount`; no new release override path.
- [ ] **Password checked before the ceremony:** `PasskeyCreationOptions(current)` runs before `registration()`; `AddPasskey` carries **no** password; the challenge, user id and excluded ids are validated before `createPasskey`.
- [ ] **Bodies from parsed fields:** the attestation is rebuilt (no raw `registrationResponseJson` forwarded); all binaries unpadded base64url; `transports` omitted when null/empty, ≤ 8 × ≤ 32.
- [ ] **Silent cancel:** `CreateCredentialCancellationException` → no message, prompt stays, the prompt's `TextFieldState` is left uncleared (the model never stores the password).
- [ ] **Messages:** `credential`/`name` 422 and every non-cancel `PasskeyFailure` → registration failure and the prompt closes; `challengeId` → expiry and closes; wrong password, offline, throttle → the prompt stays.
- [ ] **passkeyCount upsert** merges into the stored `security` object (keeps `twoFactorEnabled`, `passwordRules`).
- [ ] **Delete:** Keep sends nothing; DELETE body is exactly `{"password": …}`; billing error wins over password; success → `signOut(discardPending = true)` in `appScope` → Welcome; failures keep the account and the prompt; `stop()` bumps the generation so a late result cannot finish a new request.
- [ ] **Secrets:** passwords live only in screen-owned `remember { TextFieldState() }` and reach models as 10c's `SecretField`; never in `SecurityState`/`DeleteState`, `rememberSaveable`, `SavedStateHandle`, `Bundle`, logs or `toString`; `clearSecrets()`/`stop()` on leaving.
- [ ] **Plan:** NoLink only for credits; failed notice uses the website-free line; no Billing section, no Buy button, no `chronoflow.app`; credits never invented from bad JSON; pull to refresh awaits `refreshNow()`.
- [ ] **Copy:** only generated resources; `android_passkeys_intro` replaces the Face ID line; Dutch present; plurals for passkeys and credits; no hard-coded "Added", "today" or month names.
- [ ] **Dates:** 1a's fixed month tables (not `DateTimeFormatter` with a locale); "today" by local date in `deps.zone`.
- [ ] **Looks:** dashed empty card drawn in `drawWithCache` (no allocation per frame); dp only from `@BoardMetrics`/tokens; `CfModalBottomSheet` radius 38; destructive colours from `CfTheme`, not `MaterialTheme.colorScheme`.
- [ ] **Tests:** cheapest tier; Swift names kept; no `Thread.sleep`; snackbars through the counter; one emulator journey only.
- Typical mistakes: forwarding the Credential Manager JSON as-is; sending `"transports": null`; putting registration code in `:feature:auth` (features cannot depend on features); calling `controller.signOut` from `viewModelScope` (cancelled by the wipe); showing "Buy credits" because the `credits` board variant draws it; using `settings_update_your_payment_method_on_th_*`; composing the Passkeys row whenever `passkeyCount` exists, ignoring the capability; catching `Exception` and swallowing `CancellationException`; forgetting the `PasskeyFailure` catch in 10c's `run` (it only catches `DataFailure`); keeping a `promptPassword`/`password` property in a model.
