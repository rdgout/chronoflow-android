# Assets: launcher icon, notification icon and launch moon

Generated by `tools/assets/build_assets.py` (stdlib Python, `python3 -I`). `make icons` regenerates the vector drawables and `make assets-check` (part of `make generators-check`) compares them byte for byte with the committed files. The raster launch moon is the only asset that needs `rsvg-convert`; `generators-check` never rasterizes.

## Launcher icon

Sources: `_design/canvas/icon/android/adaptive-{background,foreground,monochrome}.svg` (the `.png` files next to them are references only), `_design/canvas/icon/colors.json` and board `AppIcon`.

Conversion rules (OQ-A43: the layers are converted unchanged, nothing is redrawn):

- Every value is parsed from the SVG, never retyped. The script fails unless the background stops equal `colors.json` `top`, `mid` and `hor` in that order, the foreground stroke equals `dawn`, and the monochrome stroke is `#ffffff`.
- `ic_launcher_background.xml`: a 108 dp vector on a 1024 viewport with one rectangle path and a linear gradient. SVG `y2="1"` in bounding-box units is `endY="1024"` here. Stops: `0 #FF06091C`, `0.6 #FF221A40`, `1 #FFAA5830`.
- `ic_launcher_foreground.xml`: the moon outline, verbatim path, inside a `<group>` with `translateX/Y 341.6` and `scaleX/Y 14.2`. A vector group applies scale and then translate, the same as the SVG `translate(...) scale(...)`. Stroke `#FFF2AD73`, width 2.0, round caps and joins, no fill.
- `ic_launcher_monochrome.xml`: the same geometry with stroke `#FFFFFFFF` and width 2.2, as supplied. It is one color, so launchers can tint it (Android 13+ themed icons).
- `mipmap-anydpi/ic_launcher.xml` and `ic_launcher_round.xml`: `<adaptive-icon>` with the three layers. `minSdk` is 29, so no `-v26` qualifier is needed.

Safe zone: launchers show the middle 72 dp of the 108 dp canvas and mask it to their own shape (circle radius 33 dp at most). The stroked moon box [1, 23] in a 24-unit space maps to at most 23.3 dp from the centre, inside the 33 dp safe radius. The outer moon radius is 142 px of 1024 (14.98 dp), and the visible size is 41.6 % as on iOS (`docs/research/08-design-system.md` §11.2). `AdaptiveIconTest` guards these numbers and `LauncherIconInflationTest` inflates the icon on Robolectric to catch path errors.

## Notification icon

`app/src/main/res/drawable/ic_stat_moon.xml` is a 24 dp vector on a 24 viewport with the moon outline path verbatim from `_design/canvas/icon/layers/moon-white.svg`: stroke `#FFFFFFFF`, width 2, round caps and joins, no fill. Android uses only its alpha channel for the status bar. Lint `IconColors` and `NotificationIconTest` guard it. It stays unused until Phase 12b.

## Launch moon

`app/src/main/res/drawable-xxxhdpi/launch_moon.png` (light) and `drawable-night-xxxhdpi/launch_moon.png` (night) are 1152 x 1152 px, which is 288 dp at xxxhdpi. They hold the moon glyph (104 dp, offset 92) with the glow baked in (Gaussian blur sigma 9, alpha 0.45) and fit inside the 192 dp launch circle. Phase 3a shows them on the system splash and the launch overlay.

Command: `make assets` (`python3 -I tools/assets/build_assets.py icons moon`). It reads `Assets/moon/launch-moon-{light,dark}.svg` from iOS at the pin with `git show`, checks their SHA-256, and runs `/opt/homebrew/bin/rsvg-convert -w 1152 -h 1152`. `tools/assets/assets.sha256` records the pin, the rsvg-convert version, the two iOS inputs, the two substituted SVGs and the two PNGs. `make assets-check` verifies those hashes and never rasterizes or reads the iOS repo. Raster output is not part of `make generate`.

Substitution (OQ-0b-3): the iOS SVGs paint the stroke as `color(display-p3 r g b)`, which rsvg-convert 2.63.4 does not understand, so it renders a fully transparent PNG. The script checks that each file has exactly one such stroke and that its channels equal the `dawn` P3 cell of `tools/tokengen/TokenGenReport.md`, then replaces only that attribute with the sRGB hex of the same row (`#E78A45` light, `#F2AD73` night) and writes `tools/assets/moon/launch-moon-{light,dark}.srgb.svg`. The app is sRGB only (OQ-A7, iOS D10), so the sRGB value is the right one. `LaunchMoonAssetTest` guards against a blank render.

## Launch wordmark (Phase 3a)

`make assets` shapes ChronoFlow with HarfBuzz hb-view 15.1.0 from the hash-checked Fraunces 400 opsz32 TTF. `wordmark.py` parses absolute M/L/C/Z outlines, applies 32/upem scaling, −0.32 dp tracking after each of ten glyphs, the iOS overhang rule and a 31.568 dp baseline. It commits one box-relative path (three decimal places). The board's 32/40/−0.01em declaration is guarded. `assets-check` only verifies the input/output hash manifest; it never calls hb-view or a rasterizer. The tooling unit test additionally proves a fresh shaping run is byte-identical.
